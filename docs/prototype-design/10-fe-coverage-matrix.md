## 1. Shared acceptance scenarios

| Scenario | Issues | Expected prototype behavior |
|---|---|---|
| Guest finds only public ACTIVE listings and opens detail | FE-H02 | Hidden/suspended fixture never appears; no private data in presentation |
| Owner creates/selects pet and obtains explainable match | FE-H01, FE-H02 | Wrong/archived/incomplete pet path explicit; no AI/verification claim |
| Owner quotes and creates one booking; replay does not duplicate | FE-T01 | Total/policy visible; REQUESTED stays unheld; same logical action is idempotent |
| Two requests overlap; only one valid accept is simulated | FE-T01, FE-HA01 | Competing request remains REQUESTED with conflict; browser simulation does not prove DB race behavior |
| Payment failure then retry within fixed hold | FE-T02, FE-T01 | New attempt, same booking; hold deadline does not extend |
| Caregiver updates and Owner confirms; release fails then succeeds | FE-T02, FE-HA02 | Care-update timing enforced; booking remains waiting until release success |
| Report is reviewed; private evidence stays restricted | FE-HA02 | Admin-only evidence view; report IN_REVIEW blocks completion; dismissal does not alter payment |
| Mobile navigation, form errors, empty/loading, keyboard and focus | FE-H01, all issues | P0 groups work at 320 px and keyboard; WCAG 2.2 AA is a proposed target |

## 2. Gaps before real Vue implementation

1. Add and contract booking list/detail/event read endpoints or an approved alternative before FE-T01/FE-T02 integrate live data. The prototype does not invent them.
2. Admin presentation scope is confirmed as limited Filament-style references for listing moderation and reports; booking-operation state is embedded in report case detail. Existing route/API evidence does not establish that these exact Filament pages already exist.
3. Reconcile current UI input fields with final API/OpenAPI during FE kickoff; especially auth verification, booking read model, user-facing error copy and media fields.
4. Gate BE/CI/reviewer status must be checked at the actual integration commit before implementation; local docs and workspace branch are snapshots.
5. Account deletion UI is a scope question: P0 Contract §6 specifies behavior, but FE-H01/API currently do not expose a flow. It remains outside the Builder Brief until the team confirms its prototype scope.
